## Routes

Information architecture after the 2026-11 redesign (plan: `docs/workflow/plans/2026-11-08-ui-ux-redesign.md`, design: `apps/web/DESIGN.md`). Five destinations in the rail (desktop) / bottom tab bar (phone): Home, Bills, Statements, Cards, Settings. Quick actions (Upload receipt, Run SOA, Add card) are available from every dashboard page via `QuickActionsProvider`.

| `user-rows.service.ts`          | Per-request loaders for the user-scoped row sets most reads share (`due_entries`, `soa_statements`, `credit_cards`) plus their invalidate helpers                                                                                             |

SOA pipeline lives in **`src/lib/soa/`** (Gmail fetch, bank parsers, summary PDF, `calendar-sync-rows.ts` + `google-calendar.ts`). Each active card resolves a `googleAccountId` (explicit or default); `runSoaSingleMonth` switches Gmail clients per issuer search config. Mark-paid, reminders, and due sync are native in `server/services/`. Workdir: `/tmp/kame-finance-{userId}/`. See `docs/temp/pay-credit-cards-migration.md`.

`lib/soa/transaction-dates.ts` is the shared transaction-date parser (per-issuer column order, display text, chronological sort key) used by the Transactions tab, Analytics drill-down, and summary PDF. Feature code re-exports it from `features/dashboard/soa/lib/transaction-utils.ts`.

## Data loading and caching

| Piece                                  | Purpose                                                                                                                              |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `server/ssr.ts`                        | `createSsrHelpers` + `prefetchForPage`: prefetch a page's queries during the server render and return dehydrated state               |
| `components/providers/TrpcHydrate.tsx` | Client wrapper that superjson-deserializes that state into a `HydrationBoundary` so `useQuery` reads it without a network round trip; queries a layout component already created without data are seeded synchronously so SSR and hydration agree |
| `server/lib/request-cache.ts`          | `AsyncLocalStorage` memoization for one request (`runWithRequestCache`, `cachedPerRequest`, `invalidateRequestCache`)                |
| `server/services/user-rows.service.ts` | The shared row loaders built on that cache                                                                                           |
| `hooks/use-nav-data-prefetch.ts`       | Warms each dashboard route's queries on rail/tab-bar hover, focus, or touch, since Next route prefetch only fetches the shell for dynamic pages |

Dashboard pages are Server Components that call `prefetchForPage` and render inside `TrpcHydrate`. The tRPC GET handler wraps requests in `runWithRequestCache`; POST is deliberately excluded so mutations always read fresh rows. Read paths that repair rows (`statement-card-identity.service.ts`) call the matching invalidate helper after writing.
